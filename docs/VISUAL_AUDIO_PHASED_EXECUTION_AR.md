# التنفيذ المرحلي المتتابع للمرئيات والصوتيات — AshenKingdoms

**التاريخ:** 2026-10-21  
**المنصة الأولى:** Android؛ Godot 4.6؛ مطوّر بشري واحد.  
**نوع الخطة:** خطة تنفيذ مرتبة ببوابات توقف/استمرار، وليست شهادة بإكمال أي مرحلة.  
**القاعدة:** لا تبدأ مرحلة لاحقة حتى تُغلق بوابة المرحلة الحالية بأدلة مرتبطة بـ commit محدد. لا تغييرات مباشرة على `main`، ولا أصول مجهولة الترخيص، ولا استدعاءات توليد مدفوعة دون موافقة مناسبة.

## طريقة العمل

تُنفّذ كل مرحلة في فرع أو PR مستقل أو سلسلة PRs صغيرة مرتبطة بالمرحلة، مع إبقاء التغييرات ضيقة النطاق. يوضع في كل PR: الهدف، قائمة الملفات، الأدلة، الاختبارات التي نُفذت فعلًا، الاختبارات غير المنفذة، والمخاطر المعروفة. تستخدم أدوار `ASSET_AGENT_ASSIGNMENT_AR.md` كمسؤوليات تنظيمية وأدوات مساعدة فقط؛ وجود اسم أداة لا يعني أنها متصلة أو تعمل تلقائيًا. المطوّر الواحد هو من يراجع النتيجة ويقبلها.

## تفاصيل العمل داخل كل مرحلة

### F0 — خط الأساس
نفّذ وسجّل الأوامر المتاحة، مثل:
```bash
git status --short
git rev-parse HEAD
git branch --show-current
python3 tools/validate_docs.py
python3 tools/validate_free_assets.py
godot --headless --path . --editor --quit
```
ثم اتبع قائمة الأوامر في `docs/TEST_PLAN.md` بحسب توفر Godot وقوالب التصدير وبيئة Unix. لا تكتب «نجح» إلا بعد حفظ رمز الخروج والسجل.

### F1 — الجرد الجنائي
- احسب SHA-256 وحجم كل ملف مصدر؛ سجل التكرار ولا تحذف تلقائيًا.
- افصل المصادر عن ملفات Godot المولدة/cache والملفات المؤقتة والمراجع.
- ابحث عن موارد ومشاهد ومسارات مفقودة، وأخطاء استيراد، وتبعيات الإضافات والأدوات.
- اربط كل نتيجة بمسار وسبب وخطوات إعادة إنتاج وتصنيف `P0/P1/P2`.
- لا تعِد تنزيل أو إرسال أي مورد خارجي خلال الجمع دون تصريح وسبب مسجل.

### F2 — معيار الفن والصوت
- اختر مرجعًا واحدًا معتمدًا لجو «ممالك الرماد»: فانتازيا قاتمة متسقة، خامات طبيعية، رماد وغبار محسوبان، وتباين واضح للّعب.
- حدّد مقياس اللاعب والأبواب والأسلحة والبيئة، ودرجات الألوان، وخامات الأسطح، ومستوى التفاصيل عن قرب وبُعد.
- حدّد تفضيلات الصوت ونطاقات المستوى والتكرار ووقت الانتقال بين الموسيقى والقتال.
- ضع ميزانيات مبدئية ثم عدّلها بالقياس الفعلي على الجهاز المستهدف.

### F3–F8 — العينة المتكاملة
لا تُنتج مكتبة ضخمة من الشخصيات أو الأزياء أو الخرائط مبكرًا. اعتمد بالتتابع لاعبًا واحدًا، منطقة واحدة، عدوًا واحدًا، مواجهة واحدة، مجموعة صوت قصيرة، وواجهة مكتملة للمسار الأساسي. احفظ لقطات مقارنة من الكاميرا نفسها، مع توثيق الأصول وتراخيصها واختباراتها. لا تستخدم صورة توليد كبديل عن نموذج 3D أو حركة فعلية.

### F9–F12 — التثبيت والتوسّع والتسليم
بعد نجاح العينة على Android فقط، وسّع الموارد دفعات صغيرة. أصلح اختناقات الأداء قبل إضافة خرائط كثيفة أو مؤثرات إضافية. حزم المحتوى عن بعد مسار اختياري وليست شرطًا إذا كان إصدار اللعبة لا يعتمد عليها. اجمع أدلة الإصدار النهائية بعد إغلاق العيوب المطلوبة، واربط كل نتيجة بوضوح بالـ commit الذي اختُبر.

## توزيع الجهد لمطوّر واحد

هذه نسب تخطيطية وليست أدوارًا متوازية تلقائيًا:

| العمل | النسبة التقديرية |
|---|---:|
| فحص المستودع والأصول والتراخيص | 15% |
| المواصفات والمراجع وArt/Audio Bible | 10% |
| إنتاج العينة الفنية: لاعب/بيئة/عدو | 30% |
| دمج Godot والتحريك وVFX والصوت والواجهة | 20% |
| Android والأداء وإصلاح الانحدارات | 15% |
| التوثيق ومراجعة PR وأدلة القبول | 10% |

الأصل الفني المولد أو الخارجي ليس «منجزًا» حتى يمر بالاستيراد والترخيص والاختبار. أدوات مثل Blender وSpline وMeshy وTripo وAnimation Maker وQtMesh Cloud وغيرها مساعدة حسب توفرها وصيغها؛ لا تعني القائمة أن الحسابات متصلة أو أن التوليد بدأ. تظل سياسة `paid_generation_apis_allowed: false` سارية ما لم يصدر قرار موثق بخلافها.

## لوحة متابعة بسيطة

تُحدّث الحالات في PR المرحلة فقط:
- `NOT_STARTED`: لم يبدأ العمل.
- `IN_PROGRESS`: ينفذ العمل؛ لا يجوز بدء المرحلة التابعة.
- `BLOCKED`: توجد تبعية/رخصة/بيئة اختبار تمنع الاستمرار، مع ذكر السبب.
- `READY_FOR_REVIEW`: المخرجات موجودة والاختبارات موثقة، بانتظار مراجعة.
- `ACCEPTED`: اجتازت بوابة الخروج بأدلة.
- `REJECTED`: فشلت البوابة مع أسباب وخطة تصحيح.

**الحالة عند إنشاء هذه الخطة:** خطة التنفيذ مرتبة ومكتوبة؛ لا يعني ذلك أن F0 إلى F12 قد نُفذت أو أن الأصول النهائية أو اختبارات Android جاهزة.
