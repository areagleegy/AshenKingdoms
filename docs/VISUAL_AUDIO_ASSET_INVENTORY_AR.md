# سجل الجرد الفعلي للأصول المرئية والصوتية — AshenKingdoms

**لقطة الشجرة:** `main`، 2026-10-21.  
**المنهج:** قراءة شجرة GitHub كاملة من خلال Git Trees API، ثم مطابقة مسارات `assets/` مع `asset_manifest.json` ودليل شخصية اللاعب وملفات Godot التي تمت معاينتها.  
**درجة الإثبات:** جرد ساكن لمسارات الملفات؛ لا يعني أن كل المشاهد قد عُرضت بصريًا أو كل الصوتيات قد استُمعت.  
**سياسة المشروع:** `assets/asset_manifest.json` يضبط حاليًا `paid_generation_apis_allowed: false`. لا يُستدعى توليد مدفوع أو تنزيل خارجي دون تغيير سياسة موثق وموافقة مناسبة.

## 1. الخلاصة

| القياس | النتيجة في شجرة `assets/` التي تمت مراجعتها |
|---|---|
| ملفات أصول لعبة معروفة الامتدادات (GLB/glTF/OBJ/DAE، صور، صوت، فيديو) | ملف واحد ظاهر: `assets/ashenkingdoms_icon.svg` |
| ملفات نماذج شخصيات نهائية | لم يظهر ملف GLB/glTF/OBJ/DAE |
| ملفات خامات وصور لعب | لم يظهر ملف PNG/JPG/JPEG/WebP |
| ملفات صوتية | لم يظهر WAV/OGG/MP3/FLAC |
| ملفات سينمائية | لم يظهر MP4/WebM |
| إدخالات سجل الأصول | إدخال واحد للأيقونة، بحسب `assets/asset_manifest.json` |
| نموذج اللاعب الخارجي | غير موجود في الشجرة؛ دليل اللاعب يصف بديلًا هندسيًا إجرائيًا |
| المحتوى داخل اللعبة | يوجد مجسم/إضاءة/أرضية مؤقتة تُنشأ من GDScript، وهي ليست حزمة فنية نهائية |

هذا يعني أن المطلوب حاليًا هو إنشاء المحتوى الفعلي **مع حفظ الأساس الإجرائي المؤقت**، لا استبدال مكتبة أصول كبيرة ثبت وجودها.

## 2. قائمة الملفات تحت `assets/`

| المسار الفعلي | التصنيف | الحالة المثبتة من الشجرة | الإجراء |
|---|---|---|---|
| `assets/ashenkingdoms_icon.svg` | أيقونة/متجه | ملف فعلي ومدرج في manifest | الاحتفاظ به، وفحص شكله عند تغيير الهوية فقط |
| `assets/asset_manifest.json` | سجل مصدر/ترخيص | ملف فعلي؛ إدخال للأيقونة | الإبقاء على سياسة المصدر والترخيص، وتسجيل كل أصل جديد قبل الدمج |
| `assets/characters/player/README.md` | تعليمات أصل | وثيقة فقط، ليست نموذجًا | إنشاء `player.glb` مرخص ومختبر لاحقًا |
| `assets/environments/.gitkeep` | حافظ مجلد | لا يوجد أصل بيئة فعلي في هذا المسار | إنشاء أول منطقة لعب |
| `assets/materials/.gitkeep` | حافظ مجلد | لا توجد مكتبة خامات فعلية في هذا المسار | إنشاء مواد سطح مشتركة |
| `assets/ui/.gitkeep` | حافظ مجلد | لا توجد مكتبة صور UI فعلية في هذا المسار | جرد واجهة Godot أولًا ثم إضافة الصور الناقصة فقط |
| `assets/audio/music/.gitkeep` | حافظ مجلد | لا يوجد ملف موسيقى | بناء طبقات الموسيقى من دون افتراض أن ملفًا موجود |
| `assets/audio/sfx/.gitkeep` | حافظ مجلد | لا توجد مؤثرات صوتية | إنتاج أصوات الحركة والقتال والواجهة |
| `assets/audio/voice/ar/.gitkeep` | حافظ مجلد | لا يوجد حوار صوتي عربي | تسجيل/إنشاء حوار بعد تثبيت النصوص وحقوق الصوت |
| `assets/video/cinematics/.gitkeep` | حافظ مجلد | لا يوجد ملف فيديو سينمائي | تأجيل إنتاج الفيديو ما لم تتطلبه حلقة اللعب |

لا يُسجّل `.gitkeep` كأصل مرئي/صوتي، ولا تعد الوثائق والملفات المثالّية دليلًا على وجود ملفات توزيع نهائية.

## 3. المرئيات التي تتولد برمجيًا وقت التشغيل

### 3.1 العالم والإضاءة
- الملف: `scripts/core/main.gd`، الدالة `_create_world()`.
- خلفية `WorldEnvironment` من نوع لون ثابت، باللون `Color(0.035, 0.035, 0.055, 1.0)`.
- مصدر إضاءة `DirectionalLight3D` باسم `Sun`، والدوران `(-48°, -32°, 0°))، والطاقة `1.25`.
- أرضية مرئية `PlaneMesh` بمقاس `80 × 80`، و`StaticBody3D` مع شكل تصادم صندوقي.
- مادة الأرضية لونها `Color(0.12, 0.15, 0.17, 1.0))، وخشونتها `1.0`.
- لا يثبت هذا وجود تضاريس أو مبانٍ أو أشجار أو خامات أرضية مرسومة؛ إنما يثبت وجود أرضية بسيطة مولّدة بالكود.

### 3.2 بطل اللاعب
- الملف: `scripts/core/main.gd`، الدالة `_create_player()` مع `_add_player_model_or_placeholder()` و`_add_hero_fallback_visual()`.
- المسار المتوقع للنموذج الخارجي: `res://assets/characters/player/player.glb`.
- عند غياب النموذج أو تعذر تحميله، يستخدم الكود هيئة مؤقتة مبنية من `BoxMesh` و`CapsuleMesh` وأجزاء بسيطة مثل عباءة وتونيك ودرع صدر وحزام وحذاء وأطراف.
- التصادم منفصل عن الشكل المرئي؛ ينبغي الحفاظ على هذا الفصل عند استبدال الشكل.
- هذا مجسم مؤقت، ولا يثبت وجود UV أو هيكل عظمي أو رسوم متحركة أو مستويات تفاصيل LOD.

### 3.3 أشباح الرماد
- الملف: `scripts/core/main.gd`، الدالة `_create_enemies()`.
- ينشأ أربعة أعداء عند نقاط ثابتة في ساحة اختبارية.
- الشكل المرئي الحالي يُضاف عبر `_add_capsule_parts` باستخدام أجزاء كبسولية ولون رمادي مزرق.
- `scripts/enemies/enemy.gd` يحدد حركة المطاردة والهجوم والصحة؛ لا يثبت وجود نموذج فني للعدو أو رسوم متحركة نهائية.

### 3.4 الشخصيات الأخرى والواجهة
- `scenes/npc/NPC.tscn` و`scripts/npc/npc.gd`: نقطة بداية لفحص شخصية الشيخ المسافر؛ وجود المشهد لا يثبت جودة نموذج نهائي.
- `scenes/ui/MainMenu.tscn`, `scenes/ui/TouchControls.tscn`, `scenes/ui/VirtualJoystick.tscn`, `scenes/ui/DialogueUI.tscn`, `scenes/ui/ContentLibrary.tscn` وملفات سكربتاتها: واجهات/عناصر تشغيل ينبغي تدقيقها على Android وأحجام الشاشة المختلفة. لا تُعد ملفات المشاهد صور واجهة جاهزة.

## 4. الصوت والموسيقى والحوار

لا يظهر في شجرة `assets/` التي تمت معاينتها ملف صوت قابل للتشغيل؛ المجلدات تحتوي على `.gitkeep` فقط. هذا جرد ملفات، وليس اختبار استماع أو إثباتًا بأن كل سكربت في المشروع خالٍ من مرجع صوتي ديناميكي.

يُنشأ سجل منفصل لكل ملف يضاف مستقبلًا:

| الفئة | تغطية مطلوبة | بيانات القبول |
|---|---|---|
| موسيقى الاستكشاف | مساحة العالم، التوتر، الانتقال بين المناطق | مدة، صيغة، ترخيص، حلقة seamless، مستوى صوت |
| موسيقى القتال والزعماء | تصاعد ديناميكي دون قطع مفاجئ | نقاط انتقال، ذروة المستوى، تداخل المقاطع |
| البيئة | رياح، رماد، مطر، نار، كهوف، حجر ومعدن | تكرار، طبقات، مسافة/اتجاه إن كانت مكانية |
| اللاعب | خطوات ومشي/ركض/قفز/هبوط وتنفس عند الحاجة | مجموعة حسب السطح، تباين، عدم التكرار المزعج |
| الأسلحة والقتال | سحب، swing، hit، block/parry، إصابة وموت | مزامنة التوقيت، وضوح الضربة، عدم clipping |
| العدو وNPC | أصوات الأشباح، الهجوم، الموت، تفاعل الشيخ | حقوق الصوت والهوية، ملاءمة النبرة |
| الواجهة | فتح قائمة، اختيار، قبول مهمة، إنجاز، خطأ | قصر الصوت، إمكانية الكتم وضبط المستوى |
| الحوار العربي | أسطر معتمدة أولًا ثم أداء صوتي | نص/توقيت/متحدث/لغة/إذن صوت/نسخ احتياطية |

لا تُسجّل LUFS أو المدة أو الترميز بالتخمين. WAV يمكن فحصه عبر `wave` في Python؛ أما OGG/MP3/FLAC والفيديو فيحتاج إلى أداة تحليل وسائط موثوقة قبل تعبئة هذه البيانات.

## 5. حالة الترخيص

السجل الحالي يوثق أيقونة المشروع فقط. الحقول الإلزامية الحالية هي المصدر، المؤلف، نص الرخصة ورابطها، الإسناد، والسماح التجاري وإعادة التوزيع. تحقق الأداة `tools/validate_free_assets.py` من وجود الملف وسجل الترخيص، لكنها لا تقرأ الرخصة بدل المراجع البشري ولا تثبت حقوق ملف لم يُدمج بعد.

قبل اعتماد أصل جديد:
1. احفظ رابط المصدر الأصلي ونص الرخصة أو نسخة مؤرخة منه.
2. تحقق من أن الرخصة تسمح بالتعديل وبإدراج الأصل في لعبة وتوزيعه مع إصدار Android/Web المقصود.
3. احفظ SHA-256 والحجم والبيانات الفنية.
4. أدخل الأصل وبياناته في manifest في نفس PR.
5. افحصه واستورده واختبره، ثم وثّق قرار القبول أو الرفض.

## 7. معنى «كامل»

لا يمكن تعريف «كل شيء» بمجرد قائمة امتدادات. معيار الاكتمال هو: كل ملف فعلي في المستودع مُحصى وله بصمة وسجل مصدر وترخيص؛ كل مرجع إلى مورد داخل Godot مُتحقق منه أو مصنف اختياريًا؛ كل صوت تم تحليله والاستماع إليه؛ كل نموذج/خامة تم فتحه أو استيراده؛ وكل أصل مستخدم في مشهد معروف وله اختبار قبول على Android. ما لم يجتز ذلك يبقى `غير مدقق` أو `مؤقت` ولا يوصف بأنه جاهز للإصدار.
