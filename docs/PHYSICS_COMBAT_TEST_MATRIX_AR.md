# مصفوفة اختبارات الفيزياء والقتال والحركة — Ashen Kingdoms

تاريخ الإضافة: 2026-10-21

## النطاق والحالة الحالية

هذه المصفوفة تفصل بين ما يمكن اختباره في الشيفرة الحالية وما يتطلب ميزة لعب غير منفذة. الاختبارات الرأسية الحالية تشمل ثوابت الحركة الأساسية، خصائص إعدادات اللاعب والعدو، وتدفق الضرر والموت والعودة للحياة. لا تعتبر اختبارات المعادلات وحدها محاكاة فيزيائية متكاملة؛ يلزم اختبار مشهد Godot الفعلي واختبار أجهزة Android.

### بوابة CI الحالية

يشغّل `tests/physics_combat_regression_test.gd` عبر Godot 4.6 في الوضع headless. يجب أن تنتهي العملية برمز خروج صفر وألا تظهر رسائل `[FAIL]`.

التشغيل المحلي:

```bash
godot --headless --path . --script res://tests/physics_combat_regression_test.gd
```

## مصفوفة القوانين والأنظمة

| المجال | حالة التنفيذ | الاختبار المطلوب | معيار القبول |
|---|---|---|---|
| الجاذبية | مستخدمة في اللاعب والعدو | قيمة الجاذبية موجبة ومنتهية؛ سرعة السقوط تتغير بالاتجاه الصحيح | لا NaN أو Infinity ولا تسارع لأعلى أثناء السقوط |
| القفز | منفذ للاعب | سرعة قفز موجبة ثم تناقصها بالجاذبية؛ اختبار سقف منخفض ومنصة مرتفعة | لا قفز مزدوج إلا إذا صُمم صراحة؛ الهبوط يعيد الحالة الأرضية |
| الحركة الأفقية | منفذة | مقارنة الاتجاهات المحورية والقطرية مع التصادمات | لا تتجاوز السرعة القطرية سرعة المشي/الركض المحددة |
| التصادم | CharacterBody3D مستخدم | جدار، زاوية، منحدر، درج، حافة، جسم متحرك | لا اختراق مستمر ولا تعلق ولا اهتزاز غير مقبول |
| المنحدرات والسلالم | تحتاج اختبار مشهد | صعود ونزول بزاوية وارتفاعات مختلفة | الحركة ضمن حدود التصميم، ولا يعلق اللاعب على الحواف |
| السقوط والضرر | يحتاج سياسة تصميم | سقوط من ارتفاعات متدرجة، أرض آمنة وخطرة | الضرر يتبع قانون اللعبة الموثق، دون قيم غير منتهية |
| القتال القريب | منفذ بصورة أولية عبر RayCast query | مدى الضربة، اتجاه اللاعب، جدار حاجب، هدف واحد، تبريد الضربة | لا إصابة خلف الجدار، ولا إصابة خارج المدى، ولا تكرار خلال cooldown |
| الضرر والصحة | منفذ | ضرر موجب، صفر، سالب، مفرط وغير منتهٍ، الموت والإنعاش | الصحة محصورة بين صفر والحد الأعلى، ولا تتحول القيم غير الصالحة إلى فساد دائم |
| العدو | منفذ بصورة أولية | مجال الرؤية، المطاردة، التوقف عند المدى، cooldown | لا هجوم خارج النطاق ولا حركة غير منتهية |
| الركوب/النزول من مركبة | **غير منفذ حسب الكود المفحوص** | دخول/خروج، منع الدخول أثناء الموت أو الهجوم، مقعد واحد، عائق فوق الرأس، إلغاء الإدخال | مالك واحد للمقعد، تحويل صحيح بين إحداثيات العالم والمركبة، لا تداخل أو فقدان تحكم |
| الحيوان المصاحب/الركوب | **غير منفذ حسب الكود المفحوص** | اتباع اللاعب، توقف عند العوائق، الركوب والنزول، موت/اختفاء الحيوان | لا انتقال فوري غير مبرر، لا تداخل مع اللاعب، ولا فقدان ملكية الركوب |
| الشبكة | يوجد قتال شبكي، لكن ركوب الشبكة غير مثبت | سلطة الخادم، تحقق من الحالة والمسافة، رسائل دخول/خروج مكررة أو متأخرة | الخادم وحده يقرر حالة الركوب والضرر؛ رفض طلبات غير صالحة |
| Android | غير مثبت على جهاز حقيقي | عصا لمس، قفز، هجوم، ركوب، تبديل الكاميرا، انخفاض معدل الإطارات | أزرار قابلة للمس، عدم تعارض الإدخال، واختبار على أجهزة مستهدفة |

## مبادئ الاختبار

1. اختبارات حتمية للوحدات: معادلات الحركة، الحدود، التبريد، حالات الصحة.
2. اختبارات مشهد فيزيائي: `CharacterBody3D` و`move_and_slide` وطبقات التصادم فعليًا داخل Godot.
3. اختبارات خصائص/توليد بيانات: دلتا زمنية صغيرة وكبيرة، اتجاهات عشوائية محدودة، سرعة سالبة أو غير منتهية، ضرر غير صالح.
4. اختبارات انحدار: إعادة تنفيذ السيناريو نفسه بعد كل تغيير في الحركة أو القتال.
5. اختبارات تكامل الشبكة: طلبات متزامنة، فقد الحزم، تأخرها، وانقطاع العميل.
6. اختبار Android يدوي: لمس متزامن للحركة والهجوم والقفز والركوب، مع مراقبة FPS والذاكرة والحرارة.

## سيناريوهات الركوب المستقبلية

لا تضف اختبارات قبول نجاح للركوب قبل وجود تنفيذ فعلي. بعد تنفيذ نظام الركوب، أنشئ اختبارًا مستقلاً يغطي:

- دخول المركبة من الخارج ضمن مسافة تفاعل موثوقة.
- رفض الدخول إذا كانت المركبة مشغولة أو اللاعب ميتًا أو في حالة تمنع التفاعل.
- حفظ موضع اللاعب النسبي للمقعد وتثبيت الدوران دون قفزة مكانية.
- تعطيل تحكم المشي مع إبقاء تحكم المركبة فقط.
- الخروج إلى نقطة آمنة خالية من التصادم، وعدم إخراج اللاعب داخل الجدار أو أسفل الأرض.
- منع تكرار أحداث الدخول والخروج عند ضغط الزر بسرعة.
- استعادة الحالة الصحيحة بعد موت اللاعب أو تدمير المركبة أو انقطاع الشبكة.
- اختبار مالك المقعد والسلطة على الخادم في اللعب الجماعي.
- للحيوانات: تحقق من التوافق بين الهيكل العظمي، نقاط الركوب، الرسوم المتحركة، التصادم، الكاميرا والصوت.

## أدوات مقترحة

- Godot 4.6 headless لاختبارات CI الحالية.
- GUT (Godot Unit Testing) فقط إذا قرر الفريق اعتماد إضافة اختبار خارجية مثبتة الإصدار؛ لا تضف اعتمادًا جديدًا لمجرد الاختبار البسيط.
- أدوات Godot المدمجة: Remote Scene Tree، Debugger، Profiler، Visible Collision Shapes وPhysics 3D debug.
- اختبارات GDScript مخصصة للحالات الحالية، ثم اختبارات مشاهد فعلية للانحدارات والتصادم والركوب.
- GitHub Actions لتشغيل الاختبارات عند كل Pull Request.
- Android Profiler وأجهزة فعلية لقياس FPS والذاكرة والحرارة وزمن الاستجابة.

## حدود الأدلة

- لا تعني نجاحات اختبارات GDScript الحسابية أن التصادم أو القفز أو المنحدرات سليمة في مشهد ثلاثي الأبعاد.
- لا توجد نتيجة اختبار جهاز Android فعلية مسجلة في هذا المستند.
- لا توجد ميزة ركوب مركبة/حيوان يمكن إعلان اجتيازها حتى تنفذ وتُختبر.
