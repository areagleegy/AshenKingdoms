## 3. ترتيب التكامل الآمن المقترح

1. **عدم دمج الطلبين في آن واحد.** اختر طلبًا أولًا بعد مراجعة التغييرات كاملةً. لا تعتبر حالة `mergeable` في GitHub دليلًا على التكامل الدلالي.
2. بعد الدمج الأول، حدّث فرع الطلب الثاني إلى رأس `main` الجديد باستخدام إعادة أساس/تحديث الفرع في GitHub، وحلّ التعارضات يدويًا مع الاحتفاظ بالميزات من الطرفين.
3. نفّذ قرارًا معماريًا واحدًا لمدير الصوت: Autoload واحد، واجهة API واضحة، ومسبح SFX محدود، ومشغلات حلقية مستقلة للموسيقى والبيئة، واسترجاع إعدادات المستخدم.
4. افحص manifest كاملًا: كل ملف موجود، بصمة SHA-256 صحيحة، ترخيص ومصدر موثقان، والبيانات الفنية تطابق الملف الفعلي. لا تضع أصولًا مكررة تحت أسماء مختلفة لمجرد حل التعارض.
5. أعد تشغيل جميع اختبارات Godot، واختبارات الصوت/الواجهة، واللعب والانحدار، والقتال الشبكي وENet loopback، واختبارات الحزم والجرد.
6. أعد تصدير Android وWeb **على رأس التكامل النهائي**. لا تستخدم نجاح بناء فرع منفرد كدليل على نجاح الدمج.
7. راجع APK وWeb artifact، الحجم والبصمة، ثم اختبر يدويًا على Android: بدء اللعبة، اللمس، الحركة، القتال، الصوت والكتم، الإيقاف والاستئناف، الذاكرة والحرارة ومعدل الإطارات.
8. لا تُغلق بوابة الإصدار حتى تُوثق نتائج الجهاز الفعلي أو يظل القصور معلنًا بوضوح.

## 4. بوابات قبول الصوت

- [ ] يوجد Autoload صوت واحد ولا توجد مراجع مكسورة إلى المدير القديم.
- [ ] تُحمّل كل موارد WAV والموسيقى بنجاح على الرأس النهائي.
- [ ] الكتم ومستوى الصوت يعملان بعد إعادة تشغيل المشهد وإعادة إنشاء المدير.
- [ ] لا يتراكم عدد مشغلات SFX بلا حد، ولا تتوقف حلقات الموسيقى/البيئة عند تشغيل مؤثر قصير.
- [ ] لا يوجد clipping أو تفاوت مزعج في مستوى الصوت بعد الاستماع البشري.
- [ ] manifest يغطي كل ملف صوتي فعلي ويحتوي المصدر والرخصة والبصمة والبيانات الفنية.
- [ ] جرى التحقق من التكرار الحَلَقي للموسيقى والبيئة بالسماع، وليس باختبار تحميل الملف فقط.

## 5. بوابات قبول المرئيات والشخصيات

- [ ] استيراد نماذج GLB دون أخطاء؛ المقياس والاتجاه والخامات مقبولة داخل مشهد اللعبة.
- [ ] يبقى التصادم مستقلًا عن النموذج المرئي.
- [ ] لا يُعتمد مرشح اللاعب المهيكل قبل معاينة العظام والأوزان وتشوه الكتف/الورك والقدمين والسيف.
- [ ] لا تُعلن الحركات جاهزة إلا عند وجود مقاطع فعلية للاستخدام، مثل Idle وWalk وRun وJump وAttack وHit وDeath، واختبار انتقالاتها.
- [ ] اختُبرت أرضية shader والساحة على جهاز Android مستهدف وقورنت بخامة بسيطة بديلة؛ لا يُفترض أن shader أسرع لمجرد أنه لا يحتاج صورة.
- [ ] تم اختبار التباين والأيقونات وواجهة RTL بأحجام شاشة فعلية.

## 7. قاعدة تحديث هذا السجل

عند كل تغيير يطال الأصول أو الصوت أو المشاهد أو سير العمل، سجّل رأس Git الكامل وروابط تشغيل Validate وBuild المرتبطين به، وحالة كل تشغيل، وروابط artifacts. استبدل الأدلة القديمة فقط بعد التحقق من الأدلة الجديدة؛ لا تخلط نتائج رؤوس مختلفة في ادعاء نجاح واحد.
