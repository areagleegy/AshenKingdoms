# مختبر الاختبارات والذكاء الاصطناعي — AshenKingdoms

## الهدف

توحيد تشغيل اختبارات البناء والتشغيل واللعب والصيانة في تقرير واحد قابل للتكرار. المنسق يشغّل أوامر اختبار معروفة، ويجمع السجلات والمدة والحالة. الذكاء الاصطناعي ليس سلطة قبول ولا يعدّل الكود تلقائيًا.

## التشغيل

من جذر المستودع بعد تثبيت Python 3:

    python3 tools/test_lab.py --list
    python3 tools/test_lab.py --profile python

لتشغيل مجموعة CI الكاملة يتطلب Godot CLI 4.6 وأدوات shell المتاحة في PATH:

    python3 tools/test_lab.py --profile ci --timeout 180

المخرجات الافتراضية: test-lab-report.json وtest-lab-report.md وسجلات منفصلة في test-lab-results/. رمز الخروج غير الصفري يعني فشل اختبار أو انتهاء مهلته أو تعذر تشغيله.

## دورة المختبر

1. Static & tools: تشخيصات الاختبارات، benchmark للمصنف، روابط الوثائق، سجل الأصول والرخص، اختبارات الحزم والتوقيع.
2. Build & boot: استيراد Godot وتحميل السكربتات والمشاهد، ثم تصدير Web وAndroid والتحقق من وجود المخرجات.
3. Gameplay regression: smoke، صحة اللاعب والجرد والحوار والمهام والحفظ.
4. Multiplayer: قتال شبكي وENet loopback محلي.
5. Content pipeline: فهرس المحتوى والمثبت والتحقق من الحزم.
6. Acceptance & maintenance: سيناريوهات يدوية منفصلة لا يُسمح للنظام بادعاء اجتيازها دون دليل فعلي.

## سيناريوهات القبول اليدوية

- Android: تثبيت APK على هاتف فعلي، تشغيل نظيف وبعد تحديث، لمس/كاميرا/هجوم/حفظ/تحميل، تعليق واستئناف التطبيق، وتسجيل طراز الجهاز وإصدار النظام.
- Web: تقديم الملفات عبر HTTP/HTTPS، تجربة المتصفحات المستهدفة والإدخال والتحقق من Console وأخطاء الموارد.
- Multiplayer: مضيف وعميل على جهازين فعليين، انقطاع وإعادة اتصال، كمون وفقد حزم، منافذ وجدار ناري. loopback لا يثبت الاتصال عبر الإنترنت.
- Soak/performance: تحديد جهاز ومدة وحدود FPS/ذاكرة/حرارة قبل الاختبار؛ تسجيل قياسات متكررة.
- Save fault injection: في بيئة اختبار معزولة وبيانات تجريبية فقط، فحص الملف الأساسي والنسخة الاحتياطية وفشل الكتابة والمساحة المنخفضة. لا تختبر تعطيل الطاقة على بيانات مستخدم حقيقية.
- Release maintenance: مراجعة رقم الإصدار والتوقيع وسرية مفاتيح Android وSHA-256 وخطة الرجوع ونسخة احتياطية.

## خوارزمية القرار

- كل سيناريو آلي له معرف فريد وأمر معروف.
- يرفض المختبر معرفًا مكررًا أو أمرًا غير مسجل أو ملف تعريف يستدعي اختبارًا يدويًا.
- كل اختبار يعمل بمهلة محددة وسجل منفصل؛ انتهاء المهلة ليس نجاحًا.
- ينجح الملف التعريفي فقط إذا نُفذت كل السيناريوهات المحددة وخرجت برمز صفر.
- التقرير يدرج الاختبارات اليدوية صراحةً كـ not run.
- تنقيح السجلات يغطي أنماطًا شائعة فقط؛ لا تضع أسرارًا أو بيانات شخصية في مخرجات الاختبار.
- لا يوجد إصلاح تلقائي؛ أي إصلاح يحتاج فرعًا وتغييرًا قابلًا للمراجعة واختبارات تعيد إنتاج العطل.

## حدود النسخة الأولى

هذه نسخة أولى منسّقة لمجموعات الاختبار الموجودة، وليست محاكيًا لكل الأجهزة ولا اختبار اختراق. لا توجد قياسات آلية لحرارة هاتف Android أو اختبار أداء GPU في بيئة headless. حدّث كتالوج السيناريوهات عند إضافة اختبار جديد، وأضف اختبار وحدة للمختبر نفسه.
