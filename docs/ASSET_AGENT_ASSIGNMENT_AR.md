# توزيع العمل على الوكلاء والأدوات — AshenKingdoms

**تاريخ الخطة:** 2026-10-21  
**القيد:** المطوّر البشري واحد؛ يُعامل هذا الملف كتوزيع مسؤوليات بين مسارات العمل والأدوات المساعدة، وليس ادعاءً بأن جميع الأدوات المذكورة وكلاء مستقلون متصلون أو أن مهامًا بدأت تلقائيًا.  
**ترتيب المنصة:** Android أولًا، ثم Web حيث يدعم المسار الحالي ذلك.  
**بوابة الإنفاق:** `assets/asset_manifest.json` يحدد `paid_generation_apis_allowed: false`. لا نبدأ توليدًا مدفوعًا أو استدعاء خدمة قد تخصم رصيدًا قبل معرفة التكلفة ومراجعة الترخيص والحصول على الإذن المناسب.

## 1. الوكيل المنسق وحقيقة توزيع العمل

## 2. خريطة الأدوات المتاحة بحسب المهمة

### مفيدة مباشرة لأصول اللعبة
- **GitHub:** فروع وPR ووثائق وIssues وسجل CI. هو مسار التتبع وليس مولّد أصول.
- **Code Ontology Companion:** يُستخدم عند توفره لرسم علاقات السكربتات/الموارد والاعتماديات ومناطق التأثر قبل تغييرها؛ لا يُعامل كمولّد نماذج أو صوت.
- **Blender (عند توفر بيئة التنفيذ):** تنظيف الشبكات، إعادة التوبولوجيا، UV، rigging، animation، LOD والتصدير.
- **to3D:** تحويل صورة مرجعية إلى نموذج أولي عند الحاجة؛ الناتج يحتاج فحصًا وتنظيفًا وترخيصًا.
- **Meshy / Tripo 3D / Thrixel:** نمذجة/توليد مرئيات ثلاثية الأبعاد. الاستخدام مشروط بميزانية واضحة ومراجعة شروط التصدير، ثم تنظيف النموذج وفحص المثلثات والخامات والهيكل في الأداة المناسبة.
- **Spline:** تشكيل/معاينة مشاهد ومفاهيم 3D؛ لا يُعتبر ناتجها مدمجًا في Godot حتى يتم تصديره واختباره.
- **Build 3D Game Rooms:** منهج لتصميم غرفة/منطقة من المخطط والقطع إلى تصدير أصول؛ يمكن تطبيق بوابات الموافقة على منطقة اللعب الأولى بدل توليد عشوائي واسع.
- **QtMesh Cloud:** تدقيق جودة أصول 3D إذا كانت خدمة المشروع متاحة وصلاحياتها مضبوطة؛ ليس بديلًا عن استيراد Godot.
- **Cyber AI:** قد يوفر نماذج صور/صوت/فيديو/3D وفق النماذج المتاحة للحساب؛ لا يبدأ توليد مدفوع قبل عرض التكلفة والموافقة.
- **Animation Maker:** إعداد موجز التحريك، ورقة الحركات، وتوقيت اللقطات والمشاهد؛ إرشاد الإنتاج لا يثبت إنشاء ملف تحريك داخل المشروع.
- **Topview 3D Builder:** لوحات مراجعة للمشاهد ومراجع الصور/الصوت/الفيديو؛ ليس مستودع ملفات اللعبة النهائي.
- **WebCAD:** أجزاء ميكانيكية/صلبة محددة مثل أبواب أو آليات/فخاخ عند حاجة تصميمية؛ ليس أداة رئيسية لشخصيات عضوية.
- **Flatma:** أثاث وخزائن مخصصة؛ لا يستخدم إلا إذا كان عنصرًا معماريًا مناسبًا داخل مستوى اللعبة.
- **3D CAD Converter:** تحويل صيغ CAD عند الحاجة إلى أصل ميكانيكي مناسب؛ يجب اختبار التحويل والمحاور والوحدات والتصدير.

### أدوات محدودة أو غير مناسبة كمسار إنتاج أساسي
- **WalkMyPlan — Floor Plans in 3D:** يمكنه تقديم مرجع معماري أو مخطط مقياسي لغرفة/مبنى. لا يُفترض أن ناتج مخطط منزل أصل جاهز لخريطة Godot.
- **Anatomy وatlas وMolViewer:** مراجع تشريحية/علمية عند تصميم نسب أجسام أو كائنات؛ لا تنتج تلقائيًا شخصيات أو خامات قابلة للتوزيع.
- **NameSTL وHardware API وAutoQuote3D وPrintNexus Toolbox و3DPACK.ING وTraslochi Milano by Decorato:** خدمات تصنيع/طباعة/تغليف/نقل مادي وليست مسارات لبناء محتوى اللعبة الرقمي الحالي؛ لا تُستدعى لهذا المشروع إلا إذا ظهرت حاجة صريحة لمنتج مطبوع أو شحن.
- **Equation.io:** يفيد فقط إذا احتاجت ميكانيكا اللعبة إلى رسم/حل معادلات؛ ليس صانع أصول.
- **Polytweaks:** يُقيّم لتحضير/تحسين نماذج 3D إذا كانت دوال التصدير والصلاحيات تدعم الصيغة المطلوبة.
- **Polymend وMojulo وContour3D وAholo Lux3D وParallax Card وCircular Frame Simulator وAI Expert for 3DCP و3D CAD Converter:** لم يُثبت في هذه الجولة أن لكل اسم أداة تنفيذية متصلة ملائمة لخط إنتاج Godot؛ يُطلب توثيق وظائف الأداة وصيغ التصدير والشروط قبل إسناد ملف إصدار إليها.
- **Testkube Skills:** لا تُسجّل كوكيل اختبار متصل من مجرد ذكر الاسم؛ نبدأ باختبارات GitHub Actions الموجودة، ثم نربط Testkube فقط عند وجود بيئة وتشغيل وتقرير يمكن الوصول إليه.

## 3. خريطة التبعيات ومراحل العمل

```text
A0 خط الأساس + A1 جرد/تراخيص
                |
                v
A2 الهوية الفنية + ميزانية Android
                |
                v
  +-------------+-------------+
  |             |             |
  v             v             v
A3 الشخصية     A4 البيئة      A6 صوت تجريبي
  |             |             |
  +-------------+-------------+
                |
                v
     A5 الحركة + A7 UI/VFX
                |
                v
      A8 فحص Android والأداء
                |
                v
```

هذا الترتيب يسمح بالعمل المتوازي على المواصفات والمراجع، لكنه لا يسمح بإدخال أصول مشتراة/مولدة إلى الفرع الرئيسي دون سجل ترخيص وفحص فني.

## 4. تعريف حزم الأصول المطلوبة

### حزمة الشخصية
- `CHR_PLAYER_BODY`: ملف GLB، مقياس 1.8 م تقريبًا، محور أمامي `-Z`، أصل عند القدمين، تقرير عدد المثلثات والخامات والعظام.
- `CHR_PLAYER_RIG`: هيكل ثابت الأسماء ووزن جلد مقبول.
- `ANIM_PLAYER_CORE`: idle, walk, run, jump, attack, hit, death؛ تُضاف transitions واختبار blend root motion بحسب بنية اللاعب الفعلية.
- `CHR_ASH_WRAITH_BASE`: عدو أصلي silhouette واضح، rig/animation عند الحاجة، مع نسخة منخفضة التكلفة.
- `CHR_TRAVELING_ELDER`: نموذج الشيخ المسافر بعد تثبيت الدور السردي.
- `EQP_SWORD_STARTER`: سلاح أساسي بمقياس ومحور قبضة صحيحين وتصادم منفصل عن الشبكة المرئية.

### حزمة البيئة
- `ENV_ASHEN_TEST_REGION`: منطقة واحدة لا خريطة عملاقة؛ أرض، صخور، قطع آثار/جدران، طريق، نقطة دخول/خروج، نقاط قتال، إنارة وضباب.
- `PROP_RUIN_MODULAR`: أجزاء حجرية متوافقة الأبعاد ومكررة دون فواصل مرئية.
- `MAT_STONE/WOOD/LEATHER/DARK_METAL/ASH`: مواد مشتركة قابلة لإعادة الاستخدام، مع خامات مضغوطة ومراجعة وضوحها على الهاتف.
- `VFX_ASH_WIND/IMPACT/SPARK`: مؤثرات قليلة ذات قراءة لعب واضحة وسقف جسيمات.

### حزمة الصوت
- `MUS_EXPLORATION_01`, `MUS_COMBAT_01`, `MUS_BOSS_01` (يبدأ التنفيذ بمقطع واحد فقط للتجربة).
- `AMB_WIND_ASH`, `AMB_FIRE_LOOP`, `AMB_RUIN_INTERIOR`.
- `SFX_STEP_STONE`, `SFX_STEP_ASH`, `SFX_SWORD_SWING`, `SFX_SWORD_HIT`, `SFX_BLOCK`, `SFX_PLAYER_HIT`.
- `SFX_UI_SELECT`, `SFX_QUEST_ACCEPT`, `SFX_QUEST_COMPLETE`.
- `VO_AR_ELDER_INTRO_001` وأسطر الحوار الأخرى بعد اعتماد النصوص والموافقة على مصدر الصوت.

الأسماء أعلاه معرفات تخطيطية للملفات المستقبلية، وليست ادعاءً بوجودها. يُحدد كل ملف بمدته وحجم العينة وعدد القنوات والترميز ومستوى الصوت والترخيص وحالة الاستماع.

## 6. قواعد إدارة العمل

1. المهمة ليست «استخدم Spline» أو «ولّد شخصية»؛ يجب أن تحدد مخرجًا قابلاً للتحقق ومسارًا ورخصة ومعيار رفض.
2. لا يمكن اعتبار الصور المرجعية نماذج GLB، ولا اعتبار GLB نموذجًا متحركًا إلا بعد فحص rig والحركات.
3. لا تُعاد كتابة نموذج مؤقت إلا عندما يكون الأصل البديل قد اجتاز الفحص والترخيص والاستيراد.
4. لا يُنشأ إنفاق API تلقائيًا؛ سياسة المشروع الحالية تمنع APIs المدفوعة افتراضيًا.
5. يظل المطوّر البشري مالك الدمج النهائي؛ أدوات التوليد لا تدمج ملفاتها بنفسها في `main`.
6. يجب أن يحمل كل أصل `asset_id` وSHA-256 وبيانات الترخيص والمشاهد المستهلكة ونتيجة القبول.
7. تُبنى حزمة واحدة صغيرة أولًا؛ بعد قبولها تُكرر القواعد على بقية الأصول.

## 7. الحالة في نهاية هذه الدفعة

- **خط أساس main:** شجرة الملفات التي فُحصت كانت تحوي أيقونة SVG واحدة ولا تحوي ملفات صوت أو نماذج لعب نهائية.
- **منفذ على فرع PR #49:** أُضيفت 7 أيقونات SVG و10 ملفات WAV أولية، وربطت بالمكونات الحالية عبر `AudioFeedback` وHUD ومورد جرعة الشفاء.
- **يبقى مؤقتًا:** اللاعب والعدو والبيئة الأساسية ما زالوا يعتمدون على أشكال إجرائية؛ الأيقونات والمؤثرات الصوتية لا تكمل النماذج/الخرائط/الموسيقى.
- **موثق:** سياسة `paid_generation_apis_allowed: false`.
- **فحص اتصال الأدوات في هذه الجولة:** فهرس Cyber AI يتيح نماذج فئات صور وصوت و3D، لكن ميزة الإنفاق المدفوع معطلة والحساب لا يتيح توليدًا مدفوعًا حاليًا؛ Thrixel متصل لكن لا يوجد مشروع AshenKingdoms مُنشأ فيه حتى الآن. لم تُرسل طلبات توليد أو تُستهلك أرصدة.
- **سبب التوقف عند التخطيط:** المشروع نفسه يصرح في manifest بأن `paid_generation_apis_allowed: false`. لا نتجاوز هذه السياسة تلقائيًا عند توفر أداة أو رصيد؛ أي استخدام لواجهة توليد مدفوعة يحتاج تغييرًا معلنًا للسياسة وإذن إنفاق مناسبًا.
- **غير منفذ بعد:** استيراد GLB لشخصية/عدو، إنتاج الموسيقى والحوار، الاستماع إلى WAVs على هاتف، قياسات الأداء على أجهزة فعلية، أو اختبار بصري نهائي.
- **لا يدّعى:** أن كل أسماء الوكلاء أعلاه أدوات متصلة أو أن كل مهمة بدأت تلقائيًا. فُتحت Issues #40–#48 لتعيين مسؤول بشري ومتابعة المخرجات؛ لا تمثل أسماء الأدوات حسابات GitHub assignee تلقائيًا.
