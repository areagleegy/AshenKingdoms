# متابعة مراجعة إصلاح الحفظ — 2026-10-23

## القرار

بعد مقارنة ملفات `main` بطلبات السحب المفتوحة، لا ينبغي إنشاء إصلاح حفظ موازٍ قبل حسم الطلبات المتداخلة. مسار المراجعة المرجعي المقترح هو [PR #74 — Harden save integrity, validation, and recovery](https://github.com/areagleegy/AshenKingdoms/pull/74)، لأنه يتضمن تنفيذًا واختبارات أوسع من مجرد تدوير الملف.

## ما يغطيه PR #74

- كتابة JSON إلى ملف مؤقت، ثم `flush()` وفحص خطأ الكتابة قبل الترقية.
- نسخة احتياطية `.bak` واسترداد عند تلف الملف الأساسي، مع محاولة إعادة الملف السابق عند فشل الترقية.
- تحقق من إصدار المخطط، والحقول المطلوبة، والقيم العددية المحدودة، ونطاقات التقدم والصحة والإحداثيات، وبنية الجرد والمهمة والحوار.
- حد أقصى لحجم ملف الحفظ.
- اختبارات للـ JSON التالف والحقول المفقودة والقيم خارج النطاق والإصدار غير المدعوم وترحيل حفظ قديم واسترداد النسخة الاحتياطية وفشل فتح الملف المؤقت.
- استخدام مسارات اختبار معزولة بدل الكتابة إلى ملف حفظ اللاعب الفعلي.

## نقاط يجب ألا تُفهم على أنها محسومة

- لم يُدمج PR #74 ضمن هذه المراجعة.
- نجاح CI لا يثبت أن إعادة التسمية والاسترداد تعمل على كل أجهزة Android أو أنظمة الملفات؛ يلزم اختبار قبول فعلي على أجهزة مستهدفة.
- فحص الحفظ لا يغني عن مراجعة منطق تطبيق البيانات في `scripts/core/main.gd`، واختبارات حفظ/تحميل داخل اللعبة كاملة.
- ما زالت هناك طلبات حفظ متداخلة (#61 و#66 و#69 و#71 وغيرها). ينبغي اختيار مسار واحد ودمج الإصلاحات المطلوبة بعناية بدل دمج جميع الطلبات المتشابهة.
- لا يجوز وصف استبدال الملف بأنه ذري على كل المنصات؛ التصميم الحالي يهدف إلى جعل الكتابة قابلة للاسترداد، ويعتمد نجاحه النهائي على سلوك نظام الملفات.
