# تشغيل فحوصات AshenKingdoms محليًا

## التشغيل

من جذر المستودع:

```bash
bash tools/run_local_qa.sh
```

يتطلب Python 3. ويشغّل اختبارات Python والوثائق والأصول، ثم اختبارات Godot والشبكة إذا كان `godot` متاحًا في `PATH`. لا تعتبر رسالة نجاح نهائية دليلًا على اكتمال فحوص Godot إذا ظهر أنها تخطّت بسبب غياب المحرك؛ راجع عدد الفحوص المتخطاة.

لتحديد مكان السجلات:

```bash
ASHEN_QA_LOG_DIR=/tmp/ashen-qa bash tools/run_local_qa.sh
```

## ملاحظات

- يحافظ هذا المشروع على `scripts/components/inventory.gd` وواجهته الحالية (`add_item` و`remove_item` و`count_item` و`to_save_data` و`restore_save_data`). لا تستبدله بنظام `inventory_manager.gd` مختلف دون ترحيل واجهات HUD واللاعب والاختبارات.
- نظام الحفظ المعتمد هو `scripts/core/save_system.gd`. لا تضف `save_manager.gd` موازياً بمتطلبات مفاتيح غير متوافقة مع بيانات الحفظ الحالية.
- لا يُصدر هذا السكربت APK أو Web، ولا يغيّر ملفات الحفظ للمستخدم عمدًا. بعض اختبارات المشروع قد تستخدم ملفات `user://`؛ نفّذها في بيئة اختبار منفصلة إن كانت بيانات الحفظ مهمة.
- اختبار الشبكة قد يفشل إذا كانت بيئة النظام تمنع loopback أو حجز منافذ محلية. لا تتجاهل الفشل تلقائيًا؛ افحص السجل والسبب الفعلي.
- يتطلب اختبار ENet السماح بإنشاء مضيف وعميل محليين. لا تغيّر منفذ الإنتاج لمجرد تجاوز فشل اختبار؛ أصلح إعداد الاختبار أو استخدم منفذًا عشوائيًا داخل fixture الاختبار فقط.
- يمكن تثبيت أداة lint الاختيارية باستخدام `python3 -m pip install gdtoolkit`. لا توجد افتراضات حول وجود ملف `.gdlintrc` لأن هذا الملف ليس ضمن الفرع الحالي.
- عند فشل استيراد Godot، شغّل `godot --headless --path . --editor --quit` منفردًا وافحص أول خطأ في السجل، لا آخر رسالة فقط.
- لا تدفع مباشرة إلى `main` قبل مراجعة التغييرات ونجاح CI على الفرع أو طلب المراجعة.
