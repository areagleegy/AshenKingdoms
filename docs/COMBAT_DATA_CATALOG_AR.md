# كتالوج بيانات القتال — AshenKingdoms

## الحالة والنطاق

هذا كتالوج بيانات أولي للأسلحة والدروع، وليس نظام قتال موصولًا باللعبة بعد. القيم موسومة بأنها `prototype` ويجب موازنتها بعد ربطها بمنطق الهجوم والصحة والتحمل والعتاد. لا يُفترض أن مجرد وجود ملفات JSON يضيف عناصر إلى واجهة اللعب أو يغير سلوك اللاعب.

## الملفات

- `data/combat/weapons.json`: الضرر والمدى وتوقيت التحضير والنشاط والاسترداد والتحمل والترنح والذخيرة والشحنات والتبريد والمتانة والوزن.
- `data/combat/armor.json`: وزن الدرع وتقليل الضرر ومضاعفات الحركة والمراوغة ومقاومة الترنح والمتانة وحد الحمل ونسب الحمل.
- `tools/validate_combat_catalog.py`: مدقق محلي يعتمد مكتبات Python القياسية فقط.
- `tools/test_combat_catalog.py`: اختبارات وحدة لحالات صحيحة وغير صحيحة.
- `scripts/combat/combat_catalog.gd`: قارئ وقت التشغيل مسجل كـ Autoload؛ يعيد نسخ ملفات العناصر، ويعرض معرفاتها، ويوفر حسابًا أوليًا لتقليل الضرر.
- `scripts/player/player.gd`: يستخدم ملف السلاح المحدد لحساب الضرر والمدى ووقت التحضير والاسترداد؛ ويطبق تقليل الضرر من الدرع المحدد في مسار ضرر اللاعب. ما زالت الإصابة نفسها Raycast لحظية بعد التحضير، وليست Hitbox مستمرة طوال نافذة النشاط.
- `tests/combat_catalog_smoke_test.gd`: اختبار Godot لتحميل البيانات وسلامة القراءة وحساب تقليل الضرر.

## قواعد البيانات

- لكل عنصر `id` ثابت وفريد؛ لا تستخدم اسم العرض كمفتاح للحفظ أو الشبكة.
- القيم الرقمية يجب أن تكون منتهية وغير سالبة، باستثناء أن `active_seconds` و`durability_max` يجب أن تكونا أكبر من الصفر.
- `damage_reduction` يقع بين 0 و1، ومضاعفات الحركة والمراوغة بين 0.01 و2.
- السلاح من فئة `charged_skill` يتطلب عدد شحنات ووقت شحن وتبريدًا موجبًا.
- السلاح من فئة `ranged` أو `limited_throw` يتطلب سعة ذخيرة موجبة.
- نسب الحمل موجبة ومتزايدة ولا تتجاوز 100%.
- تبقى `balance_status` مساوية لـ `prototype` حتى يُوثّق اختبار توازن قابل للتكرار.

## التحقق المحلي

من جذر المستودع، باستخدام Python 3:

~~~bash
python3 -m py_compile tools/validate_combat_catalog.py tools/test_combat_catalog.py
python3 tools/validate_combat_catalog.py
python3 -m unittest discover -s tools -p 'test_combat_catalog.py' -v
godot --headless --path . --script res://tests/combat_catalog_smoke_test.gd
~~~

نجاح هذه الأوامر يثبت صحة بنية البيانات وتحميلها وتكامل قراءة ملف السلاح وتقليل ضرر الدرع مع مسار اللاعب، ضمن الاختبارات المحددة فقط. لا توجد حتى الآن واجهة اختيار عتاد، أو تطبيق لمتانة المعدات والوزن والتحمل والذخيرة والشحنات، أو Hitbox مستمرة، ولا يغني ذلك عن اختبار Android فعلي.

## الخطوة التالية قبل الاستخدام داخل اللعبة

1. إنشاء مورد بيانات أو مدير كتالوج في Godot يقرأ JSON ويُرفض عند وجود خطأ.
2. توصيل السلاح بآلة حالات الهجوم بحيث تمنع التحضير/الاسترداد بدء ضربة جديدة وتمنع تكرار الضرر داخل نافذة الإصابة.
3. توصيل الدرع وحمل المعدات بمسار ضرر/حركة مركزي واحد، مع منع تطبيق عقوبة الوزن مرتين.
4. إضافة اختبارات Godot لسلوك التوقيت والذخيرة والشحنات والتبريد والتبديل بين المعدات.
5. اختبار الشبكة بحيث يتحقق الخادم من الضرر والذخيرة والتبريد والمخزون؛ لا يثق في أرقام الضرر القادمة من العميل.
6. قياس زمن قتل الأعداء وسهولة قراءة الهجمات على جهاز Android فعلي قبل تغيير الأرقام إلى حالة غير تجريبية.
