# تكامل الذكاء الاصطناعي للحوار والأصول — قرار مجاني أولًا

**الحالة:** قرار معماري وخطة تنفيذ؛ لا يوجد اتصال حي بـ AIMLAPI في هذا التغيير.  
**النطاق:** Godot 4.6، حوار NPC والمهام، وسير عمل الأصول الفنية والصوتية.  
**قيد الميزانية:** صفر تكلفة إلزامية، ولا تُرسل طلبات API مدفوعة دون موافقة منفصلة.

## 1. نتيجة فحص المستودع

- اللعبة مبنية على Godot 4.6 وGDScript، وبها تنفيذ حوار محلي تجريبي عبر `scripts/dialogue/dialogue_manager.gd` وموارد `DialogueGraph` و`DialogueNode`.
- `DialogueManager` مسؤول عن تطبيق الأعلام والخبرة والعناصر وبدء المهام. يجب أن تبقى هذه التأثيرات محكومة ببيانات اللعبة والتحقق المحلي/الخادمي، لا بنص مولد من نموذج.
- المشروع يملك بالفعل مسار أصول مجانيًا وسجلًا للأصول والتراخيص: `docs/FREE_ASSET_PIPELINE_AR.md` و`docs/ASSET_CREDITS.md` و`assets/asset_manifest.json`.
- لا يظهر في ملفات الإعداد المفحوصة تكامل AIMLAPI أو مفتاح API. لا ينبغي إضافة مفتاح إلى Godot أو APK أو Web export أو Git.
- لا تتطلب حوارات اللعبة الحالية مزودًا سحابيًا كي تستمر؛ يجب أن تظل الحوارات والمهام الأساسية قابلة للعب دون اتصال.

هذه مراجعة للملفات المتاحة في فرع `main` وقت إعداد الوثيقة، وليست إثباتًا لتشغيل اللعبة أو لاختبارات جهاز حقيقي.

## 2. قرار AIMLAPI في ظل ميزانية صفر

وثائق AI/ML API الرسمية تقول إن الخطة المجانية متوقفة، وإنها لا تقدم حاليًا نماذج مجانية؛ الفوترة حسب الاستخدام، وقد تكون المبالغ المضافة غير قابلة للاسترداد. لذلك **لا نوصي بإنشاء مفتاح أو توصيل AIMLAPI الآن** ضمن شرط «مجانية فقط».

مصادر رسمية تمت مراجعتها:
- [مركز المساعدة: هل توجد خطة مجانية؟](https://help.aimlapi.com/article/22-managing-your-subscription)
- [الأسئلة الشائعة: حالة الخطة المجانية](https://docs.aimlapi.com/faq/free-tier)
- [النماذج المجانية المتاحة](https://help.aimlapi.com/article/38-what-models-can-i-work-with-for-free)
- [توثيق البدء السريع](https://docs.aimlapi.com/)

يجب مراجعة صفحات الأسعار والحصص مرة أخرى عند اتخاذ قرار لاحق؛ عروض المزودين تتغير. لا تُفترض أرصدة تجريبية أو مجانية غير موثقة.

## 3. المعمارية المستهدفة

### أ. الحوار داخل اللعبة — Offline-first

1. تظل `DialogueManager` وموارد الحوار الحالية مصدر الحقيقة لتدفق الحوار وشروطه وآثاره.
2. تُكتب الحوارات الأساسية والاختيارات ونهايات المهام كموارد بيانات محلية قابلة للاختبار.
3. يمكن استخدام نموذج محلي مجاني أو أداة توليد في وقت التطوير لصياغة مسودات الحوار، ثم مراجعتها وتخزين النص النهائي ضمن ملفات المشروع.
4. إذا أضيف توليد وقت التشغيل لاحقًا، فيمر عبر واجهة خلفية موثوقة، ويعود كنص محدود فقط؛ لا يسمح للنموذج بمنح XP أو عناصر أو بدء مهمة مباشرة.
5. عند غياب الشبكة أو فشل المزود أو انتهاء الحصة، يظهر الحوار المحلي البديل دون تعطيل اللعب.

### ب. تكامل سحابي اختياري لاحقًا

- العميل يتصل بخادم اللعبة/واجهة خلفية مملوكة للمشروع، وليس بـ AIMLAPI مباشرة.
- مفتاح المزود محفوظ في أسرار بيئة الخادم فقط. لا يُرسل إلى العميل مطلقًا.
- تُطبّق مصادقة، وحدود طول المدخلات والمخرجات، ومعدل الطلبات، ومهلات اتصال، وحدود إنفاق، وسجلات منقحة من الأسرار والبيانات الشخصية.
- تُحدد النماذج المسموح بها من الخادم؛ لا يقبل العميل أسماء نماذج أو عناوين URL يحددها المستخدم.
- تُرفض الاستجابات الفارغة أو الطويلة أو غير الصالحة، ويستخدم النظام نصًا محليًا ثابتًا عند الفشل.
- لا تستخدم استجابة النموذج كأمر أو سكربت أو ملف مورد أو محتوى قابل للتنفيذ.

## 4. الصور والصوتيات والأصول — دون تكلفة API إلزامية

- فضّل أصولًا موجودة ومجانية مع ترخيص واضح، أو أصولًا أصلية منشأة بأدوات محلية مجانية.
- يمكن استخدام Blender لمعالجة النماذج، وAudacity أو أدوات صوت محلية لمعالجة الصوت عند الحاجة، مع التحقق من تراخيص كل أداة وأصل على حدة.
- يمكن الاستفادة من النماذج المحلية مفتوحة الأوزان عندما تسمح رخصتها والاستخدامات وشروط جهاز التطوير بذلك؛ «مفتوح المصدر» و«مجاني للتشغيل» لا يعنيان تلقائيًا أن كل نموذج أو أصل مسموح تجاريًا.
- لا تولّد أصولًا وقت تشغيل اللعبة. أنشئها في مسار تطوير مضبوط، ثم راجع الجودة والحجم والأداء والترخيص والإسناد، وسجل الأصل في `assets/asset_manifest.json` و`docs/ASSET_CREDITS.md`.
- لا يُقبل أي أصل مولّد لمجرد أن مزودًا وصفه بأنه مملوك للمستخدم؛ راجع شروط الخدمة وحقوق النموذج المستخدم وتراخيص العناصر المرجعية.

## 5. بوابات القبول قبل إضافة أي عميل AI فعلي

- [ ] يبقى اللعب والحوار الأساسيان صالحين دون اتصال ودون مفتاح.
- [ ] لا يوجد مفتاح أو سر في ملفات اللعبة أو سجلات CI أو artifacts.
- [ ] توجد اختبارات للاستجابة الفارغة، والمهلة، والفشل، وحدود الطول، والاستجابة غير الصالحة.
- [ ] لا تستطيع الاستجابة تغيير أعلام الحوار أو XP أو الجرد أو حالة المهمة مباشرة.
- [ ] تُقاس تكلفة كل طلب وزمن الاستجابة قبل تجربة مستخدمين حقيقية.
- [ ] توثّق رخص النماذج والأصول ومصادرها.
- [ ] لا يُفعّل مزود مدفوع إلا بعد موافقة صريحة على الميزانية وحد إنفاق فعلي في حساب المزود.
