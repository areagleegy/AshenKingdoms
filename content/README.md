# حزم محتوى ممالك الرماد

هذا المجلد يشرح صيغة المحتوى القابل للتنزيل. لا يحتوي المستودع حاليًا على CDN إنتاجي أو مفتاح توقيع إنتاجي أو حزم فعلية منشورة؛ لذلك تبقى ميزة التنزيل معطلة افتراضيًا حتى يهيّئ مالك المشروع هذه المتطلبات.

## صيغة الحزمة

- الحزمة ملف ZIP واحد، ويُحسب حجم التنزيل وSHA-256 للملف كاملًا.
- يحتوي الفهرس على SHA-256 والحجم لكل ملف بعد فك الضغط.
- المسموح: GLB ذاتي الاحتواء، صور PNG/JPEG/WebP/KTX2، صوت OGG/WAV/MP3، وJSON بيانات.
- غير المسموح: GDScript، DLL، مكتبات أصلية، ملفات تنفيذية، موارد قابلة لحقن الشيفرة، روابط رمزية أو مسارات مطلقة أو مسارات تحتوي على نقطتين للرجوع.
- استخدم GLB بدل glTF ذي المراجع الخارجية لتقليل مخاطر المسارات خارج الحزمة.
- dependencies هي قائمة معرّفات حزم أخرى موجودة في الفهرس نفسه؛ لا تُنشئ دورات اعتماد.

## إعداد مفاتيح التوقيع

استخدم مفتاح RSA خاصًا مخصصًا لإصدار المحتوى. لا تضع المفتاح الخاص في المستودع أو APK أو سجلات CI. احفظ نسخة احتياطية آمنة خارج المستودع، ودوّر المفتاح وفق خطة إصدار واضحة.

    openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out ashen-content-private.pem
    chmod 600 ashen-content-private.pem

لا تنشر المفتاح الخاص. المفتاح العام فقط هو الذي يجوز تضمينه في إعدادات اللعبة.

## بناء حزمة موقّعة

جهّز مجلدًا يحتوي أصولًا معتمدة فقط، ثم نفّذ:

    python tools/package_content.py \
      --source ./my-character-pack \
      --pack-id wandering_guard \
      --version 1.0.0 \
      --type character \
      --url https://YOUR-CDN.example/packs/wandering_guard.zip \
      --output-zip ./release/wandering_guard.zip \
      --output-catalog ./release/catalog.json \
      --private-key /secure/path/ashen-content-private.pem

الرابط في الأمر مثال توضيحي فقط ويجب استبداله بعنوان HTTPS حقيقي قبل الاستخدام. ينتج الأمر ZIP حتميًا، وفهرسًا موقّعًا، وملف المفتاح العام. لا يُنتج الفهرس غير موقّع إذا غاب المفتاح أو OpenSSL. لا ترفع المفتاح الخاص.

يوقّع البرنامج بايتات JSON الدقيقة للفهرس باستخدام RSA-SHA256؛ لا تعِد تنسيق حمولة الفهرس بعد التوقيع. الفهرس الناتج من هذه الأداة يحتوي حزمة واحدة؛ لإنشاء فهرس إنتاج متعدد الحزم، اجمع سجلات الحزم كلها ثم وقّع حمولة JSON النهائية مرة واحدة باستخدام صيغة الغلاف نفسها.

## تهيئة التطبيق

في إعدادات المشروع (قسم [ashen] في project.godot):

- content/catalog_url: رابط HTTPS مباشر إلى ملف الغلاف JSON الموقّع.
- content/catalog_public_key: نص PEM للمفتاح العام الذي يطابق مفتاح التوقيع.

يجب تضمين المفتاح العام فقط. اترك القيم فارغة حتى يكون لديك فهرس منشور ومفتاح عام مطابق. مع الإعدادات الفارغة، يجب أن تبقى اللعبة الأساسية قابلة للعب دون إنترنت وتعرض المكتبة أن خدمة الحزم غير مهيأة.

## النشر والتحديث

1. أنشئ الأصول وراجع الترخيص والمصدر.
2. شغّل اختبارات أداة التغليف.
3. أنشئ الحزمة، ثم ارفع ZIP إلى رابط HTTPS ثابت.
4. تأكد أن url في الفهرس يشير إلى الملف النهائي نفسه، وأن الحجم وSHA-256 يطابقانه.
5. اختبر التوقيع والمحتوى على Android قبل نشر الفهرس.
6. انشر الفهرس الموقّع بعد توفر كل الحزم المشار إليها.
7. لا تستبدل حزمة إصدار موجودة في مكانها؛ استخدم إصدارًا جديدًا واحتفظ بالإصدار السابق للتراجع.
8. اختبر انقطاع الشبكة، الملف التالف، نقص مساحة التخزين، التحديث والتراجع، ثم احذف الإصدارات القديمة فقط عندما لا تعتمد عليها ملفات حفظ أو حزم أخرى.

## حدود النسخة الحالية

مدير المحتوى ينفذ تنزيلًا إلى ملف مؤقت والتحقق والتثبيت المحلي؛ الاستئناف بعد انقطاع الشبكة، فحص المساحة الحرة على Android، إدارة حزم متعددة الإصدارات، وتحديث الفهرس متعدد الحزم تحتاج إلى استكمال واختبارات إضافية قبل وصف النظام بأنه جاهز للإنتاج. يجب اختبار تحميل GLB على جهاز Android فعلي. لا تُفعّل تنزيلات الإنتاج قبل تهيئة الفهرس والمفتاح العام واستضافة HTTPS.
