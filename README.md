# ممالك الرماد | AshenKingdoms

لعبة تقمّص أدوار فانتازيا ثلاثية الأبعاد مفتوحة المصدر مبنية باستخدام Godot 4.6 وGDScript. المشروع **نموذج أولي قيد التطوير**: توجد حلقة لعب فردي، حوار ومهمة تجريبية، حفظ محلي، حزم محتوى اختيارية، وساحة شبكة ENet تجريبية. لا يعني ذلك أن الأصول النهائية أو اللعب الجماعي أو النشر الإنتاجي اكتملت.

> **نطاق الإصدار المستهدف:** اللعب الفردي والجماعي على Android وWeb، مع إضافة أصول جديدة مجانية ومفتوحة الترخيص وتأجيل تنزيل حزم المحتوى. هذا هو الهدف المعتمد وليس وصفًا لقدرات مكتملة؛ اللعب الجماعي في Web غير مدعوم حاليًا، وساحة ENet تجريبية.

## المنصات والحالة

- **Android:** يبني GitHub Actions ملف APK تجريبيًا لمعمارية ARM64. ملف CI غير موقّع كمخرج إصدار إنتاجي؛ يلزم اختباره على هاتف فعلي.
- **Web:** تصدير HTML5 يصلح للاستضافة الثابتة عبر HTTP/HTTPS. اللعب الفردي هو المسار المدعوم في Web؛ استضافة ENet والاتصال به معطلان في هذا التصدير.
- **Desktop / Android — شبكة تجريبية:** تتضمن القائمة الرئيسية الاستضافة أو الانضمام عبر ENet، مع ساحة منفصلة لحركة وقتال وصحة وأعداء ومهمة قتل تجريبية. يوجد اختبار اتصال محلي آلي في CI.
- **الخادم المخصص:** يمكن تشغيل مسار الاستضافة في وضع headless عبر القائمة الرئيسية. ليست هناك مصادقة حسابات أو حفظ شبكي دائم أو استضافة عامة مُدارة أو ضمان أمان إنتاجي. الملف `scripts/core/server.gd` ما زال هيكلًا تمهيديًا قديمًا؛ مسار أمر الخادم الحالي يمر عبر `scenes/ui/MainMenu.tscn` و`scripts/ui/main_menu.gd` و`NetworkManager`.

## التشغيل والتحكم

افتح المشروع في Godot 4.6 وشغّله. اختر «اللعب الفردي» أو إحدى خيارات جلسة الشبكة على منصة غير Web.

- الحركة: WASD أو الأسهم.
- القفز: Space، والركض: Shift.
- الهجوم: زر الفأرة الأيسر.
- الحقيبة: I أو Tab.
- الإيقاف: Esc.
- الحفظ السريع: F5، والتحميل السريع: F9.
- على Android تظهر أزرار لمس للحركة والقتال والتفاعل؛ سحب الجانب الأيمن يدوّر الكاميرا.

ملف الحفظ المحلي هو `user://savegame.json`. حالة الحفظ تخص اللعب الفردي ولا توفر حفظًا شبكيًا دائمًا.

## بناء خادم شبكة تجريبي headless

بعد تثبيت Godot CLI 4.6:

~~~bash
godot --headless --path . -- --server --server-port=7777
~~~

يستخدم المضيف UDP/ENet على المنفذ الافتراضي 7777. لاختبار عميل ثانٍ أدخل عنوان IP المضيف والمنفذ نفسه. العنوان `127.0.0.1` يصلح للجهاز نفسه فقط. راجع [توثيق الشبكة](docs/NETWORKING.md) وحدود الأمان والاختبار قبل استخدام هذه الشريحة خارج شبكة اختبار موثوقة.

## حزم المحتوى الاختيارية

توجد بنية أولية لمكتبة محتوى ومدير يقبل فهرسًا موقّعًا، وينزّل ZIP إلى مساحة التطبيق، ويتحقق من SHA-256 وملفات الحزمة قبل التثبيت. يمكن تحميل GLB وصوت من حزمة مثبتة.

**التنزيل الإنتاجي معطل افتراضيًا** لعدم وجود CDN أو فهرس إنتاجي منشور أو مفتاح توقيع مضبوط. لا تضع المفتاح الخاص داخل المستودع أو APK. ابدأ من [دليل حزم المحتوى](content/README.md).

- المدير: `scripts/content/`
- واجهة المكتبة: `scenes/ui/ContentLibrary.tscn`
- بناء الحزم: `tools/package_content.py`
- توقيع الفهرس متعدد الحزم: `tools/sign_content_catalog.py`
- اختبارات الحزم: `tests/content_catalog_smoke_test.gd` واختبارات Python ضمن `tools/test_*content*.py`

تظل استئناف التنزيل بعد انقطاع الشبكة وفحص المساحة الحرة وإدارة الإصدارات بحاجة إلى استكمال. النجاح في اختبارات CI لا يغني عن اختبار حزمة منشورة على Android فعلي.

## التطوير والتحقق المحلي

الأوامر التالية تفترض Godot CLI 4.6 وPython 3 وبيئة شبيهة بـ Linux/macOS:

~~~bash
python3 tools/validate_docs.py
godot --headless --path . --editor --quit
godot --headless --path . --script res://tests/script_load_smoke_test.gd
godot --headless --path . --script res://tests/gameplay_smoke_test.gd
godot --headless --path . --script res://tests/gameplay_regression_test.gd
godot --headless --path . --script res://tests/player_character_smoke_test.gd
timeout 45s godot --headless --path . res://tests/network_combat_smoke_test.tscn
bash tools/test-network-loopback.sh
godot --headless --path . --script res://tests/content_catalog_smoke_test.gd
python -m unittest tools.test_package_content tools.test_sign_content_catalog -v
python -m unittest discover -s tools -p 'test_ai_test_diagnostics.py' -v
python3 tools/validate_free_assets.py
~~~

نجاح الفحوص المحلية يخص الأوامر التي شُغّلت فقط. راجع [خطة الاختبار](docs/TEST_PLAN.md) لقائمة التحقق اليدوية، بما فيها الحوار والجرد والحفظ واللمس واختبارات الأجهزة.

## GitHub Actions

كل من Workflow التحقق وWorkflow بناء Android/Web يعمل عند فتح أو تحديث Pull Request، كما يعملان عند الدفع إلى `main`. يتوفر تشغيل يدوي عبر `workflow_dispatch`.

- `Validate Godot Project`: تحليل واستيراد الموارد، تحميل السكربتات والمشاهد، اختبارات اللعب والانحدار واللاعب والشبكة والمحتوى، وفحوص أدوات Python والتوثيق.
- `Build Android and Web`: تصدير Web وAPK تجريبي ورفع المخرجات كـ Artifacts.
- أسماء Artifacts: `ashen-kingdoms-web` و`ashen-kingdoms-android-debug`.
- الاحتفاظ بملفات البناء والتشخيص مؤقت؛ صلاحيتها الحالية 7 أيام.

لا تعتبر نجاح CI بديلًا عن تثبيت APK على جهاز Android حقيقي أو اختبار اتصال عميلين عبر الشبكة المطلوبة للإصدار.
